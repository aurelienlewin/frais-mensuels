## [Unreleased]

### Fixed
- (2026-10-31): Per-account summary keeps accounts with charges `à virer` on top; auto-only accounts (nothing to transfer) now sit below them instead of mixing in, and fully transferred accounts stay last.
- (2026-10-31): Auto-payment charges no longer show as `à virer`: the per-account summary cards skip them (no chip, no `Appui pour tout marquer viré`, card not clickable when only auto charges remain), and the `à virer` counters (summary badge, mobile tab) ignore them.
- (2026-10-30): The desktop left summary panel never actually stuck: `position: sticky` was on an inner wrapper whose parent (the grid item) was only as tall as the panel, so it had no room to move, and its `top-32` offset didn't match the real header height. Sticky now sits on the grid item, offset by the measured header height (`--app-header-h` via ResizeObserver), and the panel scrolls internally when taller than the viewport.

### Performance
- (2026-10-30): Scrolling felt heavy because the glass refresh had re-introduced `backdrop-filter` on every large panel, the sticky header and the mobile dock (the browser re-blurs everything behind them on each scrolled frame), plus a pre-existing per-row blur in the mobile charge list. Removed all live blur from scrolling surfaces (the glass look is kept with the diagonal sheen, hairline edge, top highlight and slightly more opaque tints), and big panels no longer lift on hover (that repainted a huge layer as the pointer crossed them while scrolling). The earlier "blur disabled below 960px" rule is superseded.
- (2026-10-30): Web perf pass. Background image: replaced the 570 KB `bg-snowy.jpg` with a 165 KB versioned `bg-snowy.v2.jpg` (it sits under a 72-94% dark overlay), preloaded with `fetchpriority="high"`, served `immutable` from Vercel, and no longer forced to `no-store` by the service worker (it was re-downloaded on every load). The screen chunk (`AppView` or `AuthView`) now loads in parallel with the `/api/auth/me` check instead of after it. The first-run tour and its setup prompts moved to a lazy `TourHost` chunk (`AppView` 170 -> 153 KB). Charge filtering uses `useDeferredValue` so typing stays responsive. Envelope cards use `content-visibility: auto` to skip off-screen rendering. Large-panel backdrop blur is disabled below 960px (more opaque tint instead), the main GPU cost on phones.

### Added
- (2026-10-30): `Repartir de zéro` button in the Enveloppes panel: ignores the incoming reliquats (debt and credit) of every envelope for the current month in one tap, with `Réappliquer les reliquats` to undo. Shows the amounts at stake. Built on the existing per-envelope `carryOverHandled` flag (no state change). README updated (mobile-first layout, style, start fresh).

### Changed
- (2026-10-30): Brand rework. Removed the redundant `Live` and `Actif` badges and the boxed badge cluster. New responsive `Brand` lockup: a glowing mark tile plus a wordmark built on weight contrast (extra-bold gradient `Frais` + light `mensuels`, tight tracking). Phones in portrait show the mark alone (room for the month controls), landscape/tablets add the wordmark, desktop shows the larger lockup with a quiet `Tableau privé` tagline.
- (2026-10-30): Visual refresh, same dark/glass identity. Panels and header are now frosted glass (blur + saturation, diagonal sheen, hairline edge, specular top highlight); buttons and cards get inner highlights and a press state; the mobile tab bar became a floating glass dock (floating rail in landscape); account totals are larger; headings use tighter tracking and balanced wrapping, numbers are tabular; the pop animation has a springy curve and tab switches cross-fade through the View Transitions API (skipped with reduced motion). `fm-lite-effects` also disables the new blur.
- (2026-10-30): Reworked the mobile UX mobile-first. The desktop/mobile switch moved from Tailwind's 640px `sm` to a 960px `desk` breakpoint (`--breakpoint-desk`, mirrored by `lib/useCompact.ts`), so phones in landscape (iPhone 14: 844x390) now get the mobile layout instead of the desktop one. Below it: a single-row 53px header (month prev/next, month sheet, menu) that scrolls away in landscape instead of the ~170px sticky one; a bottom tab bar (left rail in landscape) switching between Enveloppes, Charges, Comptes and Résumé, with a badge for pending transfers; the per-account sums, which were unreachable on phones, now have their own Comptes tab; a single floating quick-add button replacing the full-width bar; the quick-add dialog collapses to one row in landscape; the menu scrolls when taller than the screen. The guided tour switches tabs to find its anchors. Removed the per-panel "Replier/Voir" mobile toggles, now redundant.

### Security
- Node.js restricted to `^24.22.1 || ^26.12.1` (Volta pin 26.12.1), the releases fixing the Brotli decoder RCE CVE-2026-111497 (Node2Shell / HTTP2Shell). Dependencies updated within their semver ranges.

### Fixed
- (2026-09-29): Fixed recurring charge amount edits leaking backward into past months. A recurring charge's amount was stored once, globally (`Charge.amountCents`), and every non-archived month without its own override simply read that shared value — so editing the amount from any month's row (via `UPDATE_CHARGE`) changed it for every other open month regardless of chronological order. This made forward edits (e.g. editing October) look correct only by coincidence (November/December had no override yet and picked up the new value), but editing a later month (e.g. November) also retroactively overwrote earlier, already-settled months (e.g. October), making it impossible to plan a future price change without corrupting the past. `UPDATE_CHARGE` now takes the originating month (`ym`) and, when the amount actually changes, first locks every earlier non-archived month that doesn't already have its own snapshot/override to the *previous* amount via `amountOverrideCents` (mirroring the pattern `SET_SALARY` already used for salary changes) before applying the new amount globally — so the edit only takes effect from that month forward. Verified via `typecheck` and `build`. (`TS2688: Cannot find type definition file for 'vite/client'`) introduced by the TypeScript 7 upgrade. `tsconfig.json` declared `"types": ["vite/client"]` globally in `compilerOptions`, which is redundant (`src/vite-env.d.ts` already scopes the same ambient types to `src/` via a triple-slash reference) and leaked into Vercel's isolated per-function build of `api/*.ts`, which never imports `vite` (a devDependency) and therefore couldn't resolve it. Removed the redundant global `types` entry; `api/` functions no longer have any reason to resolve `vite/client`. Verified locally that `npm run typecheck` and `npm run build` are unaffected, and that an isolated compile scoped to `api/` alone no longer references `vite/client`.

### Performance
- (2026-09-23): `AppView` already computed the month's resolved charges/budgets once via `useMemo`, but its four child panels (`SummaryPanel`, `BudgetsPanel`, `ChargesTable`, `SavingsPanel`) each independently re-ran the same `chargesForMonth`/`budgetsForMonth` selectors from scratch on every state change instead of receiving the already-computed result. `budgetsForMonth` in particular walks every month's budget history to resolve carry-over chains, so this meant that single computation ran up to 5 times on every edit. The parent now passes the resolved rows down as props; no visual or behavioral change (verified via `typecheck`, `build`, and a `preview` smoke check).

### Security
- (2026-09-23): Updated `postcss`, `autoprefixer`, `vite`, and `@vitejs/plugin-react` to their latest compatible releases, which transitively resolved 4 npm audit findings (3 high, 1 moderate): `browserslist` unbounded memory growth / prototype-write crash, `nanoid` infinite loop on invalid size, `postcss` source-map path traversal, and `baseline-browser-mapping` denial of service. `npm audit` is now clean.

### Changed
- (2026-09-23): Updated React and React DOM to `19.3.0` (with matching `@types/react`/`@types/react-dom`), Tailwind CSS and `@tailwindcss/postcss` to `4.3.3`, Vite to `8.3.0`, and `@vitejs/plugin-react` to `6.1.1`. No behavior or visual changes intended; verified via `typecheck`, `build`, and a local `preview` smoke check.
- (2026-09-23): Upgraded TypeScript from `6.0.3` to `7.0.2` (the native Go-based compiler line). This project's `tsconfig.json` already avoided every option removed in 7.0 (`target: es5`, `downlevelIteration`, `moduleResolution: node10`/`classic`, `baseUrl`), so no config changes were needed; `typecheck` and `build` pass unchanged.

### Known deferred updates
- None at this time. `npm outdated` and `npm audit` are both clean after this batch.

### Known gaps (pre-existing, not introduced by this update)
- `tsconfig.json` only covers `src/`; the Vercel serverless functions under `api/` are not typechecked by `npm run typecheck` (they're transpiled independently by Vercel at deploy time, and this repo has no `@types/node` to typecheck them locally). This is what allowed the `vite/client` leak above to go unnoticed until a production deploy. Still out of scope to fully close (would need a dedicated `api/tsconfig.json` and `@types/node`), but worth revisiting.
